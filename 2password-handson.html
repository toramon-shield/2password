06 · Google Drive & OAuth

SRP の代わりにOAuth + PKCE、権限はdrive.fileだけ

1
システムブラウザで認可

アプリ内の埋め込み画面は使わない。Google が禁止しており、偽画面にも弱い。

2
PKCE ＋ state

認可コードを横取りされても、手元の code_verifier がないとトークンにならない。

3
最小権限 drive.file

アプリが作ったファイルにしか触れない。他の Drive ファイルは見えない。

役割の分担
機密性：E2EE（Secret Key ＋ パスワード）

可用性：ローカルの暗号文コピー ＋ Emergency Kit

Hands-on · Step 2

  
2SKD は20行で書ける（中身は監査済みクレート）


pub fn derive_auk(pw: &SecretString, sk: &SecretKey, acct: &Account) -> Result<Auk> {    acct.kdf.enforce_minimum()?;                    // m≥64MiB, t≥3 を強制    let pw = Zeroizing::new(pw.expose_secret().nfkc().collect::<String>());    // ① パスワード → Argon2id（遅く・メモリを食う）    let mut k_pw = Zeroizing::new([0u8; 32]);    argon2id(&acct.kdf).hash_password_into(pw.as_bytes(), &acct.salt_with_id(), &mut *k_pw)?;    // ② Secret Key → HKDF    let mut k_sk = Zeroizing::new([0u8; 32]);    Hkdf::<Sha256>::new(Some(acct.id.as_bytes()), sk.expose())        .expand(b"2password/secret-key/v1", &mut *k_sk)?;    // ③ 2つを XOR で合成 → AUK    Ok(Auk::from_fn(|i| k_pw[i] ^ k_sk[i]))}

  
※ 説明用に簡略化した疑似コード。正確な API は各クレートの該当バージョンの docs.rs で確認します。

Limits

  
暗号では守れないものを知っておく

  

    
守れない

      
    
        
  • マルウェア・キーロガーのいる端末
  • 解除したまま離席した端末
  • 偽サイトに自分で入力する
  • AI エージェントに画面や入力を渡す
  • パスワードと Kit を両方失う

    
だから運用で守る

      
    
        
  • OS 更新・ディスク暗号化・画面ロック
  • 自動ロック5分・クリップボード30秒消去
  • URL を自分の目で確かめる
  • 銀行操作と送金承認は人が行う
  • Kit を紙で別保管

  

  
自作の保管庫は第三者監査を受けていません。重要資産は、まず学習・検証用途から。







  
Summary

  
1Password の安全性は2本柱

  

    
①
サーバー侵害を前提にする
端末にしかない 128bit の Secret Key があるので、盗まれた暗号文は実質的に解読できない。

    
②
サーバーに鍵を渡さない
認証・通信・保存のどの段階でも、サーバーは平文も復号鍵も受け取らない。
